CHAPTER 01

关系模型：一切都是「一张表」

关系模型的能力来自一个极简的约定：无论实体还是联系，最后都装进二维表。理解了这句话，后面的拆表、连接、外键就都顺了。

先认术语：把表拆成零件

Relation

关系 = 表

整张 Worker 表就是一个关系。它是关系模型唯一的数据结构。
Tuple

元组 = 行

「W001 王鹏飞 男 34 职工 6200 …」这一行，代表一个具体的人。
Attribute

属性 = 列

Wname、Sal 各有名字与取值域。Wsex 的域只有 {男, 女}。
Domain

域 = 取值集合

列里能填什么。ENUM、UNSIGNED 就是在给域划边界。
Degree

度 / 目

列数。Worker 是 8 度关系。
Cardinality

基数

行数。Worker 有 13 个元组。
Primary Key

主键

能唯一认出一行且非空：Wno。像身份证号。
Foreign Key

外键

Worker.Dno 指向 Department.Dno。像门禁卡，卡号必须在总台登记过。

关系必须守的 6 条规矩

① 列同质
同一列的分量来自同一个域，类型一致。
② 列名唯一
同一表内不重名；不同表可以同名——这正是自然连接能自动找到公共列的前提。
③ 列无序
左右顺序不影响语义，π₃,₄ 按下标取列只是书写方便。
④ 行无序
没有「第 3 行」这种概念，除非 ORDER BY。
⑤ 元组不重复
关系是集合。这条直接解释了为什么 π 投影会自动去重：π₃,₄(R) 是 3 行而不是 6 行。
⑥ 分量原子
一个格子只能放一个值（1NF）。这条直接解释了为什么 m:n 联系必须单独建表。

关系模型的三要素（讨论题 1）

01

数据结构

唯一结构就是二维表。实体用表，联系也用表 → 项目 2 任务 4 把 4 实体 + 1 联系变成 5 张表。
02

数据操作

关系代数 σ π ∪ ∩ − × ⋈ ÷，落地成 SQL 的 DDL / DML / DQL。
03

完整性约束

实体、参照、用户定义三类，落地成 PK / FK / UNIQUE / ENUM / UNSIGNED。

三要素缺一不可：只建表不设约束，数据很快就会变成一锅粥；只会约束不会运算，表就只是死档案。

三类完整性规则（讨论题 2）· 点开看本例

① 实体完整性 点开
主键非空且唯一
Worker.Wno 不能重复、不能为 NULL；Department.Dno、Goods.Gno、Factory.Fno 同理。Sale 用联合主键 (Wno, Gno)，两列都不能空，且同一「职工 + 商品」组合只能出现一次。
意义：保证每一行都能被唯一认出来，不会出现「两个 W001」。
② 参照完整性 点开
外键要么为空，要么必须存在
Worker.Dno 只能是 D01~D04 或 NULL，写 D99 会被拒；Goods.Fno 只能是 HE01 / TCL2 / XM01 / GL03 / HW04 / MD05；Sale.Wno、Sale.Gno 必须能在父表里找到。
实务影响：它决定了建表顺序（父先子后）和插入顺序。项目 3 任务 2「取消外码约束」正是为了临时绕开这个限制。
③ 用户定义完整性 点开
业务自己定的规矩
Wsex ENUM('男','女')Dname / Fname UNIQUEPrice UNSIGNEDNum DEFAULT 0Sal DEFAULT 5000NOT NULL
分别对应：性别二选一、名称不许重名、单价不能为负、数量不填按 0、工资缺省 5000、编号姓名必须有值。

等值连接 vs 自然连接（讨论题 3）

等值连接
显式写 R ⋈R.C=S.C S；两列名字可以不同；结果保留两边所有列，同名列会重复出现两份。
自然连接
自动找所有同名属性做等值连接，不写条件；公共列只留一份；没有同名列时退化成笛卡尔积。
联系：自然连接是等值连接的特例，多加了「自动找同名列 + 去掉重复列」两个动作。本例 R(A,B,C,D) 与 S(C,D,E) 的公共列是 C、D，所以 R ⋈ S 结果是 5 列（A,B,C,D,E）而不是 7 列。
CHAPTER 02

E-R 建模：把一句人话画成图

诀窍只有一句：名词 → 实体或属性，动词 → 联系，「每个…有多个…」→ 基数，带数据的动作 → 联系属性。

需求逐句拆解

需求原话提取结果判定
每个部门有多名员工，每个员工只能属于一个部门部门—员工「属于」1 : n
每个员工可销售多种商品，每种商品也可被多名员工销售员工—商品「销售」m : n
厂家可供应多种商品，每一种商品只能有一个厂家供应厂家—商品「供应」1 : n
员工销售商品有销售数量、时间「销售」联系自身的属性不能挂到员工或商品上

互动 E-R 图 · 把鼠标放到节点上

矩形 = 实体，菱形 = 联系，连线旁的数字 = 基数，小椭圆 = 联系属性。节点会依次浮现，连线会「画」出来。

👆 把鼠标移到矩形或菱形上，看看它有哪些属性、转换后会去哪里。

为什么「销售数量、时间」必须挂在联系上？

点两个按钮，看两种设计的下场。这是整个建模环节最值钱的一个判断。

员工表里塞商品

王鹏飞 男 34 职工 6200 … 商品：G01001 / G01003 / G02003
吴娜丽 女 48 经理 9400 … 商品：G03001 / G04003
一个格子里塞了 3 个编号 → 违反「分量原子」（1NF）；若改成 3 行，姓名工资又要重复 3 遍 → 冗余 + 更新异常。

独立一张销售表

员工表保持干净，一人一行；销售表每行只描述「谁 · 卖了什么 · 卖了多少 · 什么时候」这一件事：
W001 / G01001 / 15 / 2022-10-31W001 / G01003 / 10 / 2022-10-31W001 / G02003 / 20 / 2022-10-31
数量挂的是「(员工, 商品)」这个组合，天然属于联系。

建模 6 个常见翻车点

漏掉「部门」
需求明确给了部门编号 / 名称 / 电话，别只画 3 个实体。
给 1:n 也单独建表
「属于」表行数会和员工表一模一样，纯冗余。
把 m:n 省略
一个员工卖 5 种商品就得写 5 行员工信息，或一格塞 5 个值。
把数量当商品属性
它是联系属性，不是商品属性。
1:n 方向画反
「每个员工只能属于一个部门」→ 部门是 1 端，员工是 n 端。
忘记标主键与基数
任务 3 明确要求标注主键和联系类型。
CHAPTER 03

E-R → 关系模式：三条规则走天下

转换不是靠背，靠一句口诀：1:n 把「1」的主键塞进「n」端；m:n 必须另起一张表；联系自带属性跟着联系走。

联系类型怎么做主键外键
1 : 1合并到任意一端，或一端加另一端主键并加 UNIQUE该端原主键新增列
1 : n在 n 端表加 1 端主键；不新建表n 端原主键n 端新增列
m : n新建联系表 = 两端主键 + 联系属性两端主键组合两列各作外键
自联系同表内加一列指向自身主键「职工—领导」原主键引用本表

为什么 1:n 不建表、m:n 必须建？

1:n 建表 = 白干
若建「(部门编号, 员工编号)」表，因为每个员工只出现一次，它和员工表行数完全相同，只是把对应关系又抄了一遍。
m:n 不建表 = 违规
把商品编号塞进员工表，一人卖 5 种就要重复 5 行姓名工资，或一格塞 5 个编号（违反 1NF）。只有独立表能同时满足原子性与无冗余。

范式：为什么是 5 张表而不是 1 张大宽表

1NF · 原子
格子不可再分。拆 m:n 本质上就是为了它。
2NF · 完全依赖
销售数量依赖 (员工编号, 商品编号) 整体。若把商品名称也塞进销售表，它只依赖商品编号 → 部分依赖，应移回商品表。
3NF · 无传递依赖
员工表存部门编号就够了，别再存部门电话（电话通过部门编号传递依赖）。教材把部门单独建表正是 3NF。

关系代数演算台：六道题，亲自点一遍

σ 是横着剪（挑行），π 是竖着剪（挑列并去重），⋈ 是把两张表拼起来，÷ 专治「全部 / 每一个」。别背结果，看它怎么一步步出来。

运算符速查

∪ ∩ −

集合三兄弟

要求并兼容：属性个数相同、对应域相同。差集不满足交换律。
×

笛卡尔积

R 每行 × S 每行全部配对。度相加、行数相乘；漏写连接条件就会得到它。
σ

选择 Selection

σF(R) 按条件挑行，不丢列、不去重。
π

投影 Projection

πA(R) 挑列，自动去重（因为关系是集合）。
⋈

连接 Join

先 × 再 σ。自然连接自动按同名列等值、去重列。
÷

除法 Division

「与 S 中每一个元素都配过对」的元组。对应 SQL 的双重 NOT EXISTS。
θ

θ 连接

比较符可以是 = ≠ > <；取 = 时即等值连接。
σ→π

组合套路

定表 → σ 过滤 → ⋈ 拼接 → π 取列 → 遇「全部」用 ÷ 或差集。

表达式书写套路（图 2 习题 5）

五步：定表 → σ 过滤行 → ⋈ 拼接表 → π 取列 → 遇「全部 / 都没有」用 ÷ 或差集。以下用口径 B（中文属性名）。

(1) 王美丽所在部门编号和职务
    π_{部门编号, 职务}( σ_{姓名='王美丽'}(员工) )

(2) 年龄大于 25 岁的男职工的编号、姓名、性别
    π_{员工编号, 姓名, 性别}( σ_{年龄>25 ∧ 性别='男'}(员工) )

(3) W005 所销售的商品编号和商品名称
    π_{商品编号, 商品名称}( σ_{员工编号='W005'}(销售) ⋈ 商品 )

(4) 王伟大「没有销售」的商品编号和名称   ← 全体减已有
    π_{商品编号, 商品名称}(商品)
  − π_{商品编号, 商品名称}( σ_{姓名='王伟大'}(员工) ⋈ 销售 ⋈ 商品 )

(5) 全部员工销售的商品
  口径①「被全体员工都卖过」→ 除法
    π_{商品编号,商品名称}( 商品 ⋈ ( π_{员工编号,商品编号}(销售) ÷ π_{员工编号}(员工) ) )
  口径②「所有被卖过的商品清单」→ 投影去重
    π_{商品编号, 商品名称}( 销售 ⋈ 商品 )
第 (4) 题的精髓：「A 中没有 B」= 全体 A − 已与 B 关联的 A。它在 SQL 里对应 NOT IN / NOT EXISTS / LEFT JOIN … IS NULL 三种写法，项目 5 任务 13 会原封不动再用一次。

CHAPTER 05

建库建表：给每个字段选对「容器」

DDL 负责结构。项目 3 的 15 个任务可归成四组：建库与开关 → 5 张 CREATE TABLE → 恢复检查 → ALTER 改结构。

CHAR vs VARCHAR（讨论题）· 看格子怎么被填满

CHAR(n) · 定长
不足补空格，读取定位快，比较时忽略尾部空格。适合长度固定的编号、电话、状态码：Dno CHAR(3)、Wno CHAR(4)、Gno CHAR(6)、Fno CHAR(4)、Wtel / Dtel CHAR(11)。
VARCHAR(n) · 变长
按实际长度存，另加 1~2 字节长度前缀，省空间但略慢。适合长短差异大的文本：Dname、Gname、Fname、Addr、Wjob。
补充：utf8mb4 下括号里的 n 数的是字符，一个汉字也算 1 个字符；建库选 utf8mb4 才能完整存下中文商品名与生僻字。

其余类型与约束

INT
Wage 年龄、Snum 销售数量、Num 库存数量。可加 UNSIGNED 禁负、DEFAULT 给默认值。
DECIMAL(6,1)/(6,2)
Sal 工资、Price 单价。金额绝不用 FLOAT：0.1+0.2 在浮点里是 0.30000000000000004，对账会出偏差。
ENUM
Wsex ENUM('男','女')、Hobby ENUM('音乐','阅读','运动')，天然实现用户定义完整性。
DATETIME
Sale.Sdate。插入 '2022-10-31' 自动补成 00:00:00。
UNIQUE / NOT NULL
Dname、Fname 取值唯一；编号与姓名非空。
DEFAULT 0 / 5000
Goods.Num 默认 0；任务 10 给 Sal 加默认 5000。

外键依赖顺序 · 箭头依次点亮

FOREIGN_KEY_CHECKS 是什么：SET FOREIGN_KEY_CHECKS = 0 只是本次会话暂时跳过校验，外键定义仍在表结构里。它让你可以任意顺序建表、灌数据；任务 8 必须改回 1，否则脏数据会溜进去。

数据更新：把空表喂饱，再改对、删干净

  
DML 三件套 INSERT / UPDATE / DELETE。这一章最值钱的不是语法，而是两个习惯：先父后子，以及改之前先 SELECT 预览。


  
插入的四种姿势（讨论题 1）

  

    
单行 VALUES
临时补一条，逐条写较慢。

    
多行 VALUES ⭐
一条语句灌完一张表。本项目最简单方便。

    
INSERT … SELECT
表间复制，无需中间文件。

    
LOAD DATA / 向导
大批量外部 CSV，需路径与权限。

  

  
列清单要不要写？写 INSERT INTO t VALUES (…) 要求值个数、顺序与表结构完全一致；写 INSERT INTO t(c1,c2,…) VALUES (…) 只列要给的列，未列的取默认值或 NULL。任务 3 特别提醒「注意带空值数据记录行的插入」，用列清单最稳。


  
默认值 / 自增 / NULL（讨论题 2）

  

    
默认值
省略该列 或显式写 DEFAULT 才触发。写 NULL 是「给空值」，不是取默认值。NOT NULL 且无默认值的列漏写会直接报错。

    
自增列
不要手动填具体值；可写 NULL / 0 / 省略。批量插入时 LAST_INSERT_ID() 只返回第一行生成的 ID；回滚、DELETE 会留空洞，不保证连续。

模糊条件（讨论题 5）

  

    
LIKE '%经理%'
任意位置含「经理」，会同时命中「经理」和「总经理」。任务 11 说「包括经理」正适合它；若只想精确匹配用 = '经理'。

    
% 与 _

BETWEEN 30 AND 40
含两端，等价 >=30 AND <=40。任务 13「30~40」要连 30 和 40 一起删。

    
NOT IN 的坑
集合里只要有一个 NULL，整体结果恒为 UNKNOWN → 返回空集。改用 NOT EXISTS 或先滤掉 NULL。

  


  
DELETE vs TRUNCATE（讨论题 6、任务 13–14）

-- 任务 14：清空 Workercopy 所有数据记录
TRUNCATE TABLE Workercopy;   -- 或 DELETE FROM Workercopy;

  
比较项DELETETRUNCATE

    
类别DMLDDL
WHERE可带，删部分行只能整表清空

    
回滚事务中可回滚隐式提交，不可回滚

    
方式逐行删，写日志，触发 DELETE 触发器重建表数据文件，快，不触发行级触发器

    
AUTO_INCREMENT保留计数归零

    
外键引用按约束逐行检查被子表引用时通常直接报错

SELECT 的真正执行顺序 · 点「下一步」

  
你写 SQL 的顺序是 SELECT→FROM→WHERE→GROUP BY→HAVING→ORDER BY→LIMIT，但数据库不是按这个顺序执行的。这个错位解释了一大半语法错误。

  

  

  
三条常考结论：① WHERE 过滤行、HAVING 过滤组；② 聚合函数不能出现在 WHERE 里；③ SELECT 里的非聚合列原则上必须出现在 GROUP BY 中（ONLY_FULL_GROUP_BY 会强制检查）。

双重 NOT EXISTS：把「全部」翻成 SQL

  
任务 13「销售了所有厂家商品的职工」是全套最难的一题。逻辑链是三层嵌套，点按钮逐层展开：

  

  

  
-- 关系除法的 SQL 写法：找不到「我没卖过的商品」= 我卖过全部商品
SELECT Wname FROM Worker w
WHERE NOT EXISTS (                      -- ③ 不存在这样的商品…
  SELECT * FROM Goods g
  WHERE NOT EXISTS (                    -- ② …使得该职工没卖过它
    SELECT * FROM Sale s
    WHERE s.Wno = w.Wno AND s.Gno = g.Gno   -- ① 相关子查询，依赖外层 w
  )
);

-- 等价写法：分组计数
SELECT w.Wname FROM Worker w JOIN Sale s ON w.Wno = s.Wno
GROUP BY w.Wno, w.Wname
HAVING COUNT(DISTINCT s.Gno) = (SELECT COUNT(*) FROM Goods);

  
用本题数据算一下：Goods 共 12 件商品、6 个厂家，20 条销售记录里覆盖厂家最多的是李海明（4 个）。所以无论口径 A（卖过全部商品）还是口径 B（每个厂家至少卖过一件），结果都是空集。空结果也是正确结果，别以为 SQL 写错了 —— 这恰恰是很好的验算点。


  
IN / ANY / ALL / 比较符怎么选（讨论题 3）

  
写法语义等价形式场合

    
= (SELECT …)等于唯一返回值—标量子查询，任务 12

    
IN等于集合中任意一个= ANY精确枚举，任务 2

    
> ANY比某一个大即可> MIN(…)「比任意一个…大」

    
> ALL比全部都大> MAX(…)任务 14

    
EXISTS子查询至少返回一行—相关子查询判断存在性

    
双重 NOT EXISTS不存在「不满足条件的元素」关系除法 R ÷ S「全部 / 所有」

  

  
两个高频陷阱：① NOT IN 集合含 NULL → 整体结果为空集，改 NOT EXISTS；② 子查询返回空集时 > ALL (空集) 为真，而 > (SELECT MAX(...) FROM 空表) 得到 NULL 不成立，两者不完全等价。


  
多表连接 & 自连接（讨论题 1、2）

  

    
JOIN 与 WHERE 连接
内连接下 FROM A,B WHERE A.x=B.x 与 A JOIN B ON A.x=B.x 等价；但逗号写法一旦漏条件会静默产生笛卡尔积且不报错。JOIN…ON 把连接条件与筛选条件分开，更清晰。多表一律起别名、列名带前缀。

    
自连接
同一张表必须起两个不同别名（w 与 m）；用条件区分角色（m.Wjob='经理'）；必要时 w.Wno <> m.Wno 排除自己；同部门多个经理会产生重复行，按需 DISTINCT。任务 10 就是它。
